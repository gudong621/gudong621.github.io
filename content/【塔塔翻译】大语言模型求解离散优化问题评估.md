## 摘要

本研究调查了不同模型（包括 Llama-3 系列模型和 CHATGPT）在通过自然语言数据集求解离散优化问题时的能力，测试了不同表达形式的影响。与参数范围有限的形式化数据集不同，我们的数据集包含了多种类型的离散优化问题，具有广泛的参数规模，包括大规模参数实例，并集成了增强数据。

本研究旨在：
1. 概述大语言模型在大规模问题上的能力
2. 为希望自动求解离散优化问题的研究者提供建议
3. 将性能作为未来研究的基准

这些数据集包括原始数据集、扩展数据集和增强数据集。其中，原始数据集和增强数据集用于评估，而扩展数据集可用于微调新模型。

在实验中，我们在各种数据集上比较了强模型与弱模型、CoT 方法与无 CoT 方法的性能。结果表明，较强的模型表现更好是合理的。与普遍共识相反，研究还显示 CoT 技术并不总是有效，这取决于模型的能力。此外，乱序数据集在易于理解的问题上提高了模型性能，尽管有时方差较高，这是不稳定的表现。

因此，对于希望提升离散优化问题自动求解能力的研究者，建议参考本研究的结果，包括附录中展示的折线图，以及研究中得出的结论以获取相关建议。

**关键词**: 离散优化，大语言模型，思维链，思维程序，基准数据集

## 1 引言

运筹学 (OR) 问题几乎渗透到所有应用领域，特别是在工业生产和自动化控制管理系统中。在这些问题的类型中，离散优化问题是一个重要的类型。这些问题通常通过建立数学模型来解决，然后根据问题规模选择合适的求解方法，如启发式算法、动态规划、神经网络方法等。

自动求解离散优化问题有助于决策过程，能够基于现有信息动态调整资源分配，从而降低成本、提高效率。此外，大语言模型 (LLM) 的进步为该领域的进一步发展提供了广阔前景。在求解 OR 问题时，LLM 展现出独特的能力，能够自动整合海量信息来构建数学模型，并根据参数规模智能选择求解方法。

自 2022 年 11 月以来，Chat Generative Pre-trained Transformer (CHATGPT) 一直主导着在线讨论。许多研究致力于改进经典下游任务的性能，如句子分类、情感分析和命名实体识别等。借助思维链 (CoT)——一系列中间推理步骤、思维程序 (PoT)——使用语言模型生成文本和编程语言语句并最终得出答案、或检索增强生成 (RAG) 等技术，研究者取得了显著进展。

在关注传统 NLP 任务之后，研究者转向数学问题，在基础数学数据集（如 MathQA 和 GSM8K）上测试了不同模型。2024 年，ORLM 基于 LLaMA-3-8B-Instruct 微调而成，用于处理 OR 问题，但受限于其僵化的响应。然而，这些研究都没有在具有广泛参数规模的离散优化问题上测试 LLM 的性能。它们关注的是连续思维能力而非决策能力。我们的工作致力于填补这一空白，同时建立一个新的数据集。

在我们的工作中，建立了大规模数据集，包括基于 OR 库和 VRP 的各种类型的自然语言形式的离散优化问题。然后，我们扩展了背景并改变了问题的叙述方式。最后，通过改变句子顺序对数据集进行了增强。在性能测试方面，主要考虑了隐式形式，尽管也考虑了显式形式但存在一些缺点。

虽然你可能会质疑仅仅改变问题中给定的参数会有什么区别，但这会影响 LLM 所使用的方法，并进一步影响解的质量。结果在附录中给出，以便你随时查阅参考。对于超时限制，设置为 300 秒，旨在验证 LLM 是否能在有限时间内选择正确的方法来处理问题。基于实验结果，表明方法的选择不是随机的。

此外，我们测试了数据集的性能，包括原始数据集和乱序数据集。为了评估 LLM 的响应，采用了 4 个指标，包括通过率 (PR)、准确率 (AR)、平均绝对百分比误差 (MAPE) 和超时率 (TR)。借助这四个指标，全面分析了乱序数据集相对于原始数据集的优缺点，以及不同模型使用不同技术（如 CoT 和 PoT）的性能。此外，还基于这四个指标评估了弱模型和强模型之间的比较。然后，对错误类型以及不同模型的超时率进行了解释。这些分析旨在充分说明数据集本身，并识别解质量的决定性因素。

总之，我们的贡献可以总结如下：

### 贡献 1: 测试 LLM 在大规模离散优化问题上能力的评估框架

我们引入了一个新的自然语言数据集，具有广泛的参数规模，用于测试 LLM 在各种类型离散优化问题上的能力。它包括以下问题类型：分配问题、一维装箱、机组调度、斯坦纳树、无约束二次 0-1 规划、容量约束车辆路径问题 (CVRP)、多车场车辆路径问题 (MDVRP)、周期车辆路径问题 (PVRP)、飞机降落、广义分配、多维背包、容量约束仓库选址和二维切割装箱约束断头台问题。这些问题有不同的类型，如原始型、扩展型和乱序型。

扩展数据集自动改变背景，从其他数据集转换而来，因此可以无限生成，而乱序数据集随机化句子以干扰 LLM，测试它们是否仅仅依赖模式匹配来理解优化问题。

### 贡献 2: 基于四个指标的多种比较和分析

基于我们的评估，我们展示了乱序数据集在什么问题类型上优于原始数据集，在什么情况下 CoT 技术优于无 CoT 技术，弱模型和强模型之间的差异，每个问题的误差以及对每个结论的解释性分析。这项研究可以使未来的工作受益，以提高整体性能。我们的分析类似于"ChatGPT 的数学能力"研究，但在主题本身有所不同。

### 贡献 3: 关于选择哪种模型和哪种技术的洞察

对于任何使用不同技术的模型，我们在附录 B 中给出了带有平均线的清晰图表。这些图表使感兴趣的读者能够独立决定使用哪种模型和技术来自动求解大规模离散优化问题。我们提供了发现的总结，专注于某些方面，并不与特定需求对齐。因此，完整的结果被公开供公众访问。

## 2 相关工作

离散优化问题的自动化一直是研究的长期焦点。其重要性在于该领域可应用于解决工业和管理中的复杂问题。在 LLM 流行之前，学者通常依赖开创性和有效的算法，在 Python 中构建了一系列存储库，如 PULP、CVXPY 和 Gurobi，为公众提供方便使用的工具。对于用户来说，他们更关注工具的有效性。

2021 年，Hendrycks D 等人构建了一个新的数据集 MATH，每个数据都有逐步解决方案。在 MATH 数据集上的测试结果表明，即使使用巨大的 Transformer 模型，机器学习方法在解决数学竞赛问题上的准确率也很低。此外，Transformer 中的缩放无法解决 MATH 问题，增加预算和参数数量是不切实际的。考虑到传统方法的低准确率和弱迁移性，学者逐渐转向 LLM。

最初，研究者只关注简单的数学问题。Chowdhery A 等人测试了 Pathways 语言模型在基于一些开源数据集（如 MathQA 和 GSM8K）的基础数学上的能力。他们训练了 PLM，并在少样本场景中展示了在语言理解和源代码生成等任务上的出色性能。

Frieder S 等人观察到，截至 2023 年，研究人员一直忽视 ChatGPT 在数学推理方面的能力，然后评估了六个子数据集。他们发现 2023 年 1 月 9 日版本的 ChatGPT 无法处理高质量的证明和计算，其在不同高级数学问题上的能力不稳定，因此 ChatGPT 当时只能充当助手。

后来在 2024 年，Ahn 等人进行了关于 LLM 在数学推理方面的进展和挑战的工作。它总结了面向 LLM 的技术、影响 LLM 解决数学的因素和关注点，提供了对当前状态、成就和未来挑战的整体视角。然后，Mirzadeh 等人介绍了 GSM-Symbolic，这是一个从符号模板改进的基准，允许生成多样化的问题集，旨在提供关键见解和更可靠的指标来衡量模型的推理能力。

基于数学能力，研究者尝试直接给 LLM 分配任务，包括优化和回归，以测试 LLM 的能力。Yang 等人将 LLM 视为优化器，在 GSM8K 数据集上提高了线性回归和销售员问题的准确性。同时，他们发现最好的提示策略是"深呼吸，一步一步地解决这个问题"。然而，研究人员观察到一个显著的缺点：在线性回归问题中，权重 w 和偏置 b 的不同初始化会极大地影响达到相同性能所需的迭代次数，参数数量与迭代次数呈指数关系。这种特性对时间有限的场景不友好。

类似地，Liu 等人利用 LLM 直接帮助贝叶斯优化，通过迭代提出和评估有希望的解决方案来直接微调参数。Xiao 等人介绍了一种新的机器学习范式：口头机器学习 (VML)。其方法与上述工作类似，不同之处在于本文专注于各种回归任务，如线性回归、多项式回归和正弦回归。他们可视化了 LLM 学习的确定性边界，以显著展示 VML 在解决传统机器学习问题上的强大能力。

除了传统问题，Pluhacek 等人专注于利用 LLM 生成新型混合群体智能优化算法。几个任务被分离出来，精心设计了提示，但仍需要专家监督和严格评估。

同时，另一组学者旨在通过微调 LLM 来解决其在工业中求解 OR 问题时的不稳定性和高延迟问题。在优化问题方面，Tang 等人利用自建的工业数据集和数据增强技术，基于 LLAMA3-8B、Deepseek-Math-7B-Base 和 Mistral-7B 扩大具有不同分类和背景的数据集。其微调的 LLAMA3-8B 在简单 OR 问题上略微优于 GPT4。这项研究为行业提供了多上下文 OR 问题数据集和训练特定 LLM 的潜力。

Guo 等人通过参考强化学习方法开发了 DeepSeek-R1，最终克服了监督学习的缺点，提高了 LLM 的数学推理能力。在基础数学方面，Luo 等人开发了强化学习进化指令反馈 (RLEIF) 框架来训练许多开源模型，称为 WizardMath，以增强 LLM 的数学 CoT 推理能力。

也有研究调查了使用大语言模型在运筹学问题上的人机协作，而不是直接利用 LLM 来处理它们。Wasserkrug 等人将 LLM 与 OR 优化相结合以增强决策。虽然我们需要创建准确高效的优化模型，但 LLM 实际上可以帮助加速专家创建形式模型的工作。

## 3 基准架构与数据表示

虽然之前的研究通常处理带有小规模优化任务（变量数量少）的数学问题，但本研究旨在测试 LLM 在涉及大量变量的各种离散优化问题上的能力。我们将测量 LLM 的性能，分析错误类型及其根本原因，以及带有变量数量分布的数据集描述。为了实现我们的目标，需要回答以下问题：

- **RQ1**: 数据集是如何构建的？这个数据集有什么独特之处？
- **RQ2**: 提示工程能帮助改进解决方案或降低错误吗？LLM 对输入文本敏感吗？
- **RQ3**: 什么因素在 LLM 求解离散优化问题的性能中起重要作用？
- **RQ4**: 我应该采用什么策略？

### 3.1 数据集

**统计数据**: 数据集收集自 OR 库和 VRP 的一部分，包括一维装箱、分配、机组调度、斯坦纳树、UBQP、一系列 VRP 问题、飞机降落和其他组合问题。OR-Library 是 J.E. Beasley 最初描述的各种 OR 问题的测试数据集集合，VRP 由 NEO 研究组收集。

**数据生成与扩展**: 对于数据生成，使用标注样本手动制定标准数据集。样本包括几个隐式问题和一个显式问题（即数学模型被明确给出）。对于数据扩展，Ilia Shumailov 等人发表在 Nature 上的工作揭示了大规模使用 LLM 在互联网上发布内容会污染用于训练其后继者的数据收集。这一发现表明，通过 LLM 生成数据应该认真对待。通过这种方式，首先选择那些数据包含背景的其他数据集。然后，利用 GPT-4o-mini 提取这些背景，并要求创造性地继续故事，存储为数据库。最后，对于任何隐式问题，从数据库中随机选择一个新的背景来替换旧背景。然而，这些类型的数据集仍然太完美。我们旨在为这种自然语言数据引入一些噪声，以实现数据增强。

**数据增强**: 句子将被随机分成片段，这会破坏句子的逻辑。它旨在测试 LLM 是否完全理解问题本身，还是仅仅进行模式匹配，这将在下一节中分析。

### 3.2 评估基准

在我们的研究中，评估基准被定义为系统地比较我们的数据集在不同模型和技术上的性能。

初步实验表明，LLM 不可能在没有代码的情况下实现复杂的迭代。我们的策略是在获得结果后优化问题，通过执行 LLM 生成的代码，并需要一些必要的指令来指导模型生成正确的代码。例如，数据可能对 LLM 来说太大而无法读取，因此预先以文本格式存储。这避免了读取数据时的幻觉，并降低了生成成本。此外，我们为代码执行设置了阈值，这样死循环不会干扰其他测试数据。评估通过提示来规范化 LLM 生成的输出，而不干扰性能，指令和代码在附录中给出。

**评估指标 (EM)**: 我们采用四个评估指标，即精确匹配、通过率、平均绝对百分比误差和超时率，分别表示为 AR、PR、MAPE 和 TR。

- **准确率 (AR)**: 旨在捕捉 LLM 是否找到最优值。当目标是最小化结果时，如果执行结果小于参考值，则输出被视为正确。类似地，对于最大化，如果结果超过参考值，则有效。

- **通过率 (PR)**: 用于测量生成的代码是否可执行。如果生成代码的执行失败次数超过指定阈值（如 6 次），则计为失败；否则，解决方案的代码将被接受。详细来说，当执行失败时，错误信息将提供给 LLM 以帮助它们纠正错误。

- **平均绝对百分比误差 (MAPE)**: 作为 AR 的补充。对于连续数据，它可以表示预测值与实际值之间的差异，这可以进一步阐明 AR 指标中的结果。

- **超时率 (TR)**: 用于测量在有限时间（此处设为 300 秒）内完成的解决方案的百分比。该指标旨在评估不同模型是否能够在不同问题集的有限时间框架内自主选择最合适的优化方法。

**基线**: 我们采用了不同的技术，如 CoT 和 PoT，以及模型如 GPT-4o-mini、DeepSeek-R1、使用 float16 精度的 LLAMA3-8B-Instruct 和 ORLM 来测试我们的原始数据集。详细来说，前两个模型被认为是强模型，而后两个模型被认为是弱模型。CoT 提示由 GPT-4o-mini 完成，它给出了处理某类问题的完整步骤指令。在下文中，LLAMA3-8B-Instruct 将简化为 LLAMA3-8B。

### 3.3 错误类别

当生成的代码、结果或解决方案出错时，这些错误将被记录。以下是几种错误类型和描述：

| 错误类型 | 描述 |
|---------|------|
| IndexError | 当尝试访问列表或序列的索引超出范围时抛出 |
| FileNotFoundError | 当请求文件或目录但找不到时抛出 |
| OverflowError | 当计算超出数据类型限制时抛出，通常在数值运算中 |
| NameError | 当找不到局部或全局名称时抛出，意味着变量或函数未定义 |
| ValueError | 当函数接收到正确类型但不适当的值时抛出，如将非数字字符串转换为整数 |
| AttributeError | 当进行无效属性引用时抛出，意味着对象上不存在该属性 |
| KeyError | 当尝试使用不存在的键访问字典时抛出 |
| SyntaxError | 当 Python 解释器遇到代码中的无效语法时抛出，阻止执行 |
| TypeError | 当操作或函数应用于不适当类型的对象时抛出，如将字符串添加到整数 |
| ImportError | 当无法导入模块或包时抛出，通常由于找不到或内部有问题 |
| PulpError | 在优化问题上下文中抛出，表示不可行或无界解决方案等问题 |
| SolutionError | 当问题的解决方案无效时抛出，通常与违反约束有关 |
| ResultError | 当函数未产生预期形式的结果时抛出，通常由于 LLM 输出错误 |

初步实验表明，IndexError、ValueError、TypeError、KeyError 和 SyntaxError 是这些错误中最频繁的。

### 3.4 表示形式

我们假设一个问题不同形式的表达会导致不同的性能。一个问题可以是显式的或隐式的。

通常，具有显式形式的数据集成本更高但无限制，而具有隐式形式的数据集更便宜但仅限于 PoT 技术。此外，前者会遇到长序列问题，LLM 会偷懒，省略必要的数据，而后者将受限于 OR 问题求解器的性能，无法充分利用 LLM 的计算优势。因此，两种表达形式都有各自潜在的应用。

## 4 实验

在分析结果之前，我们假设参数数量越大，性能越差，包括 PR 和 AR 的下降，以及 MAPE 的增加，这是由长序列问题引起的。此外，我们假设 CoT 应该基于先前的研究提高整体性能。在验证这一初始假设之前，必须澄清的是，在我们的实验中，LLM 在处理显式形式的问题时倾向于省略数据，或者在重现数据时可能由于幻觉问题而产生遗漏。此外，LLM 可能通过伪造数据走捷径，这就是为什么显式形式的问题后来不用于测试的原因。此外，这种方法成本也很高，不建议用于解决离散优化问题。

### 4.A 定量分析

**对于 PR 指标**: DeepSeek-R1 在来自原始数据集的隐式表达问题上表现出压倒性的性能，仅在飞机降落、广义分配和多维背包任务上不如 GPT-4o-mini。这与现有研究一致，强调了 DeepSeek-R1 卓越的数学推理能力。值得注意的是，CoT 提示并不普遍提高 PR。详细来说，强模型可能受益于 CoT，而弱模型可能不会。这是因为 CoT 将问题分为几个步骤，弱模型无法一致地处理这些步骤。虽然在乱序数据集上 PR 有所增加（对于强模型 GPT-4o-mini），但对于弱模型来说通常相反。此外，无论是否应用 CoT，ORLM 都表现出持续的格式合规问题，可能是由于训练中的过拟合，使得 PR 评估对该模型意义不大。

总之，就 PR 指标而言，理解问题的综合能力非常重要（这就是为什么强模型表现更好），乱序数据集可能在某些类型的问题上通过无意中提前提供优化目标而使强模型受益。基于 2025 年的先前工作，我们了解到 LLM 广泛遵循贝叶斯后验更新，偏差主要是由于先验校准不当而非更新有缺陷。因此，当问题被随机化，优化目标无意中提前时，贝叶斯概率分布被更新，导致 LLM 更精确地解释随后呈现的输入。具体的潜在机制不在我们的工作范围内，可能在未来的工作中解决。然而，PR 并不一定意味着更好的性能，因为解决方案的结果尚未比较。

**对于 AR 指标**: GPT-4o-mini 在原始隐式数据集上使用 CoT 表现出显著优势，而 DeepSeek-R1 在 PoT 上表现出色。总的来说，DeepSeek-R1 更强大。通常，CoT 具有辅助性质，因此无法帮助达到精确解。然而，虽然它的提示可能影响 Python 中内置优化求解器的选择（其中一些可以通过提供问题类型和格式化数据来调用，而另一些需要人工编码约束），这种选择会导致不同的性能。与 PR 类似，乱序数据集帮助强模型实现更好的性能，但对弱模型则相反。虽然我们无法解释 GPT-4o-mini 的情况，但 ORLM 的计算限制和格式问题共同解释了其普遍较差的 AR。尽管如此，它在机组调度问题上的表现表明，如果考虑模型规模，其数学潜力略低于 DeepSeek-R1。因此，微调模型在某种程度上是有效的。

总之，虽然强模型在解决离散优化问题上可能表现更好，但 CoT 对他们来说不一定有效，这取决于模型本身。对于弱模型，我们建议使用无 CoT 技术且不使用乱序数据集，而对于强模型，CoT 技术可能有助于提高性能，如果需要进一步改进，可以探索乱序数据集。

**对于 MAPE 指标**: 空值 (-) 意味着结果不可接受，这是由于超时或极端异常值≥500%，需要排除数据。结果表明，LLAMA3 和 ORLM 经常产生空 MAPE 值，通常是由于异常值。对于强模型，DeepSeek-R1 通常在使用 CoT 或无 CoT 技术的情况下表现更好，而 GPT-4o-mini 仅在使用 CoT 技术时表现更好。然而，GPT-4o-mini 在乱序数据集上的表现比原始数据集差。因此，结合 AR 指标，结果的方差相对较高，这意味着如果使用它，需要承担风险。

总之，对于强模型和弱模型，都强烈建议使用 CoT 技术以确保在任何条件下的性能鲁棒性。当然，从业者可以在强调预测准确性时战略性地采用乱序数据集，但需要承担不稳定性的风险。

## 5 结论与建议

基于实验结果，我们为希望自动求解离散优化问题的从业者提供以下建议：

1. **模型选择**: 强模型（如 GPT-4o-mini 和 DeepSeek-R1）在大多数任务上表现更好，但成本更高。如果预算有限，可以考虑微调 LLaMA-3-8B（类似 ORLM）。

2. **技术选择**: 
   - 对于强模型：可以尝试 CoT + PoT 组合，在某些问题上可能提升性能
   - 对于弱模型：直接使用 PoT，避免使用 CoT

3. **数据策略**:
   - 使用原始数据集作为基线
   - 对于强模型，可以尝试乱序数据集以探索潜在的性能提升
   - 对于弱模型，坚持使用原始数据集

4. **风险管控**:
   - 设置合理的超时限制（如 300 秒）
   - 监控错误类型，针对性修复常见问题
   - 对关键任务，考虑使用多个模型投票

5. **未来方向**:
   - 需要更深入的理论分析来解释乱序数据集的效果
   - 探索 LLM 与传统求解器的混合方法
   - 扩展数据集覆盖更多问题类型和规模
