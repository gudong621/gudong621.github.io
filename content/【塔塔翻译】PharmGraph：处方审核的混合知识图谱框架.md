## 摘要

用药错误对患者安全构成重大威胁，使得药师审核 (PV) 成为关键但负担过重的最后防线。由于大语言模型 (LLM) 固有的事实不可靠性、缺乏可追溯性以及复杂推理能力薄弱，将其直接应用于这个零容忍领域是不可行的。为了解决这些挑战，我们引入了 PharmGraph-Auditor——一个专为安全且基于证据的处方审核而设计的新颖系统。

我们系统的核心是一个可信赖的混合药物知识库 (HPKB)，基于虚拟知识图谱 (VKG) 范式实现。该架构通过严格的映射层，战略性地统一了用于集合约束满足的关系组件和用于拓扑推理的图谱组件。为了构建这个 HPKB，我们提出了迭代模式精炼 (ISR) 算法——一个能够从医学文本中实现图谱和关系模式协同演化的框架。

对于审核任务，我们引入了基于知识库的验证链 (CoV)——一种新的推理范式，将 LLM 从不可靠的生成器转变为透明的推理引擎。CoV 将审核任务分解为针对 HPKB 的一系列可验证查询，生成混合查询计划以从最合适的数据存储中检索证据。

实验结果展示了强大的知识提取能力，并表明 PharmGraph-Auditor 有望帮助药师实现更安全、更快速的处方验证。

**关键词**: 处方审核、大语言模型、混合知识库、验证链、信息检索、可解释 AI

## 1. 引言

大语言模型 (LLM) 的出现为药物相关任务提供了有前景的解决方案。凭借处理大量非结构化文本的能力，LLM 非常适合消化来自处方信息、医学文献和临床指南的信息。目前，大多数工作集中在简单的诊断任务或一般生物医学事实核查上，这些主要基于医学问答对。然而，临床环境中处方的可信度仍然严重依赖人工检查——这一过程正因现代药物证据的复杂性而日益紧张。

用药错误（如剂量不正确和不良相互作用）代表着持续的医疗挑战，每年导致数万起不良事件甚至死亡。抵御这些风险的最后一道防线是药师审核 (PV)，药师在此过程中仔细审查处方以拦截潜在错误。然而，随着药师必须应对数据洪流——包括不断扩展的药典、复杂的患者病史和不断演变的临床指南——这最后一道人工防线正承受越来越大的压力。这种认知超载（通常因高工作量而加剧）增加了关键细节被忽视的风险，导致严重的患者伤害。因此，迫切需要能够用系统化、基于证据的安全层增强药师专业知识的智能系统。

尽管一些工作旨在预防用药错误，但它们很少直接针对关键的 PV 阶段。如图 1 所示，像 Pais 等人这样的系统主要在使用 AI 模块进行数据输入期间的处方标准化。相比之下，我们的工作解决了最后的验证步骤——在这个步骤中，直接应用 LLM 由于以下根本性限制而不可行：

1. **事实不可靠性**: LLM 容易产生"幻觉"，生成看似合理但不正确的信息——在患者安全受到威胁的情况下这是不可接受的。

2. **缺乏可追溯性**: 知识不透明地编码在模型参数中，无法将结论追溯回源文档。这违反了循证医学原则，因为不可追溯的建议本质上不可信。

3. **复杂推理能力薄弱**: 审核需要多跳推理来连接不同事实（如患者肾功能、药物特性和剂量指南）。LLM 在没有事实施架的情况下难以可靠地执行此类结构化推理。

为了弥合这些差距，我们引入了 PharmGraph-Auditor。我们的系统基于虚拟知识图谱 (VKG) 范式构建和查询混合药物知识库 (HPKB)。在我们的知识分层框架指导下，我们认识到药物知识天生需要双重建模：关系组件 (ℛ) 处理严格的"约束"（如剂量限制、数值条件），图谱组件 (𝒢) 捕获语义"拓扑"（如相互作用、层级关系）以进行多跳推理。这种混合架构确保了复杂推理所需的灵活性和数值审核所需的严谨性。

我们的方法解决了智能审核的完整生命周期。对于构建，我们提出了迭代模式精炼 (ISR) 算法，动态演化混合模式以捕获领域异质性。这是通过分块感知多智能体框架实现的，确保每个提取的事实都可追溯到其来源。对于应用，我们引入了基于知识库的验证链 (CoV)。CoV 不是不透明的生成，而是将审核分解为可验证的子任务，执行透明的混合查询，并利用患者画像驱动的证据选择树 (P-EST) 来剪枝无关规则。至关重要的是，当患者数据缺失时，系统被设计为显式标记**信息缺口**，将安全置于幻觉性结论之上。

我们在临床专家注释的真实世界住院患者处方数据集上评估了 PharmGraph-Auditor。结果表明，我们的框架始终优于传统的基于规则的 CDSS，F1 分数提高了 13.4%。为了提供更深入的见解，我们检查了系统在平衡安全与效率方面的能力。它在保持有效缓解药师警报疲劳所需的高精确度的同时，显著超越了人类专家的召回率。虽然这些结果强调了其在临床环境中的有效性，但 PharmGraph-Auditor 的混合架构使其能够适应其他需要严格约束满足和高级语义推理的复杂领域。我们的代码和数据将在发表后发布。

## 2. 方法论

### 2.1 理论基础：混合 VKG 模型

虽然向量数据库在主流 RAG 架构中占据主导地位，但它们天生缺乏临床审核所需的确定性，因为语义相似性无法严格强制执行精确的数值约束。因此，结构化符号知识的基础至关重要。然而，药物知识具有双重性质，包括严格的条件规则和高度连接的语义概念。单一结构化数据模型证明不足：关系数据库难以处理深度递归推理，而纯图谱数据库缺乏用于复杂范围过滤的有效索引机制。

为了解决这个困境，我们将混合药物知识库 (HPKB) 框架化为虚拟知识图谱 (VKG) 范式的专门实现，采用混合物化策略。

形式上，我们将 HPKB 定义为元组 **H = ⟨ℛ, 𝒢, φ⟩**：

- **ℛ** 是关系组件（约束存储），一组关系 {R₁,...,Rₙ}，存储高完整性原子事实。它处理需要严格模式验证的数据，如剂量阈值。

- **𝒢** 是图谱组件（拓扑存储），一个标记属性图 𝒢=(V,E)，捕获医学实体的语义拓扑。它处理需要多跳推理的数据。

- **φ** 是映射函数，φ: V ↔ ⋃Rᵢ，一个双射函数，在图谱顶点和关系元组之间建立显式链接，确保系统作为统一整体运行。

这种混合架构不仅仅是工程选择，而是从处方审核任务的算法差异性推导出的理论必然性。为了系统地指导模式设计，我们提出了知识分层框架（表 1），根据数据的逻辑性质将其分配给 ℛ 或 𝒢。

#### 2.1.1 集合约束满足（为什么用关系型？）

像禁忌症检查或剂量验证这样的审核任务本质上是集合约束满足问题。临床规则通常表现为布尔和范围过滤器的堆栈（例如，允许 IF 年龄 ≥ 65 AND 肌酐清除率 < 30 AND 肝损伤 = '重度'）。

我们将此类数据分配给 ℛ，因为关系数据库管理系统 (RDBMS) 在数学上针对集合论运算进行了优化。它们通过 B 树索引有效执行动态谓词逻辑，对范围查找实现 O(log N) 复杂度，其中 N 是表基数。在图谱数据库中对连续数值范围建模本质上需要将值离散化为节点或执行低效的全局属性扫描 (O(N))，导致实时审核中不可接受的延迟。

#### 2.1.2 拓扑遍历（为什么用图谱？）

相反，像相互作用筛查或过敏检查这样的任务是拓扑遍历问题，涉及路径发现和传递性。例如，检测过敏需要遍历层级：患者 → 有过敏 ← 子类概念 ← 成分属于药物。

我们将此类数据分配给 𝒢。图谱模型利用无索引邻接，其中连接的节点在内存中物理指向彼此。这允许每跳以常数时间 O(1) 遍历关系，完全独立于总图谱大小（|V|或|E|）。相比之下，在 ℛ 中实现深度递归（例如，通过递归 CTE）需要为每跳进行迭代索引查找。由于每个连接操作产生 O(log N) 开销，深度为 k 的路径的累积成本缩放为 O(k·log N)。随着医学术语层级加深和数据集大小 N 增长，这个对数惩罚累积，使得关系递归与图谱的常数时间指针解引用相比计算上脆弱。

### 2.2 可信赖的 HPKB 构建

#### 2.2.1 阶段 I：迭代模式精炼 (ISR)

为医药领域预定义刚性、全面的模式是不切实际的，因为医学知识的复杂性和异质性极高。为了解决这个问题，我们提出了迭代模式精炼 (ISR) 算法。这个半自动、专家支持的流程旨在演化一个稳健的模式 S_final，平衡高信息召回率和结构紧凑性。

**分层采样策略**: ISR 流程使用基于 ICD-10 分类的分层采样策略。我们选择一个代表性语料库（如 100 份文档），均匀分布在五个主要治疗领域：抗肿瘤药（复杂方案）、抗感染药（禁忌症重）、心血管药（相互作用重）、神经系统药和呼吸系统药。

**人机协同：缺口检测与抽象**: ISR 算法在提议 - 验证 - 固化循环上运行，利用 LLM 和人类专家的互补优势。流程从最小"种子模式"开始。对于样本中的每个文档：

1. **LLM 作为缺口检测器**: LLM 智能体将文档文本与当前模式进行比较。除了提取适合的数据外，其主要作用是识别"模式缺口"——当前模式无法表示的有价值信息（如剂量调整前提、输注速率）。通过起草结构化的模式变更提案，LLM 减轻了专家的认知负荷，防止人工构建中常见的遗漏。

2. **专家作为架构师**: 人类专家审查提案以强制执行语义抽象。我们的初步分析表明，未经检查的 LLM 容易产生"模式碎片化"（如为肾调整和肝调整提议单独的表）。专家通过将特定缺口提升为通用结构来缓解这个问题。例如，专家不是接受不同器官功能的分散字段，而是定义通用约束节点。这种抽象设计确保图谱组件 𝒢 保持紧凑，同时统一表示基于肾、年龄或体重的限制。

**决策策略与稳定化**: 模式提案的接受由我们的知识分层框架管理。专家将缺口分为两类以更新理论模型 H = ⟨ℛ, 𝒢, φ⟩：

- **场景 A（约束发现）**: 如果智能体遇到定义数值边界的文本（如"如果肌酐清除率 < 30，剂量减少 50%"），则将其分类为关系约束，更新 ℛ。

- **场景 B（拓扑发现）**: 如果智能体遇到描述实体间关系的文本（如"药物 A 抑制药物 B 的代谢"），则将其分类为图谱关系，更新 𝒢。

这个迭代过程持续进行，直到模式表现出"快速稳定"——定义为 N_stable 个连续文档通过而不触发有效模式变更提案的状态。

#### 2.2.2 阶段 II：分块感知知识填充

建立稳定模式 S_final 后，我们进入全面填充阶段。主要目标是可验证性。我们定义溯源函数 Π(f) = (doc_id, section, source_text)，要求每个提取的事实 f（无论是 ℛ 中的元组还是 𝒢 中的边）必须携带其派生的确切源文本。

**1. 文档预处理和分块**: 初始步骤是将异构源文档（通常是 PDF）转换为结构化、机器可读的格式。我们利用 MinerU——一个开源工具包，将 PDF 文档解析为 Markdown，同时保留标题和表格等层级结构。鉴于药物文档通常遵循标准化组织，这种结构化表示允许我们将文本分割成不同的语义块（如剂量和给药、禁忌症、药物相互作用），实现有针对性的、上下文感知的后续处理。

**2. 分块感知多智能体框架**: 为了克服单体 LLM 中常见的上下文窗口限制和注意力漂移，我们引入了分块感知多智能体框架。

- **调度器智能体**: 作为编排器，该智能体分析每个文本块的标题并将其路由到适当的专科智能体。例如，标记为"药物相互作用"的块严格路由到相互作用智能体，最小化噪声。

- **专科智能体**: 我们部署了一套智能体（如禁忌症智能体、剂量智能体、相互作用智能体），每个智能体配置有专门的提示和 S_final 的特定子集（源自 ISR 算法）。
  - 剂量智能体被提示提取结构化元组（如 [age_min, dose_val]），针对关系组件 ℛ。
  - 相互作用智能体被提示提取三元组（如 (患者，有状况，过敏)），针对图谱组件 𝒢。

至关重要的是，为了确保可验证性，每个智能体被严格执行输出溯源元数据 Π(f)（原始源文本）以及提取的事实。

**3. 混合持久化和映射层**: 最终组件充当智能体框架和混合存储引擎之间的桥梁。它解析和验证提取的 JSON，根据模式定义将数据路由到 ℛ 或 𝒢。为了操作化映射 φ，我们采用统一身份策略，其中共享全局标识符在两种存储模式之间锚定实体，隐式确保数据一致性和无缝交叉引用。

### 2.3 基于知识库的处方审核

我们系统的最终目标是利用可信赖的 HPKB 审核处方。形式上，给定处方实例 P = (患者信息，药物列表)，任务是生成审核报告 (A, I)，其中 A 包含基于证据的审核发现，I 识别信息缺口（验证所需的缺失患者数据）。

为了实现安全、透明且抗幻觉的目标，我们提出了基于知识库的验证链 (CoV) 框架。如图 3 和算法 1 所示，CoV 将 LLM 不透明的"黑盒"推理转变为透明的"白盒"流程，包括四个不同阶段：

#### 2.3.1 阶段 1：LLM 驱动的任务分解

CoV 不是用"检查这个处方"这样的单体指令任务化 LLM，而是首先采用专门的分解智能体。该智能体的唯一职责是将高级审核目标分解为验证计划。该计划是针对患者档案和每种处方药物定制的具体、可验证子任务（如剂量验证、禁忌症检查）的结构化列表。

#### 2.3.2 阶段 2：混合查询生成

这个阶段是我们混合架构的运营核心。对于验证计划中的每个子任务，基于规则的确定性查询引擎生成精确的数据库查询。至关重要的是，该引擎根据任务类型选择适当的查询语言，与第 2.1 节中定义的理论分层保持一致：

- **对于约束任务**（如剂量）：生成针对关系组件 ℛ 的 SQL 查询（如"SELECT * FROM DosageRules WHERE Drug='Metformin' AND ..."）。

- **对于拓扑任务**（如过敏分析）：生成针对图谱组件 𝒢 的 Cypher 查询以检索推理所需的药理学层级。例如，为了筛查潜在过敏，查询检索药物的组分层级（如"MATCH (d:Drug {name: 'Metformin'})-[:HAS_INGREDIENT]->(i:Ingredient)-[:BELONGS_TO]->(c:Class) RETURN i, c"）。

通过依赖确定性规则而非 LLM 生成来构建查询，我们消除了语法错误或幻觉数据库字段的风险。

#### 2.3.3 阶段 3：通过 P-EST 进行证据检索和整理

原始数据检索通常不足。例如，查询通用药物的剂量规则可能返回数十行，涵盖各种适应症和人群。将这种"嘈杂"的上下文馈送给 LLM 会增加认知负荷和错误率。

为了解决这个问题，我们引入了患者画像驱动的证据选择树 (P-EST)（图 4）用于结构化证据整理。P-EST 模拟临床决策逻辑来剪枝无关规则：

1. **精确匹配搜索**: 首先尝试找到完全匹配患者特定档案的规则（如"年龄 65，肌酐清除率 25ml/min"）。

2. **层级回退**: 如果未找到精确匹配（在现实世界数据中常见），P-EST 启动回退搜索，沿决策树向上移动以找到最具体的适用父规则（如"任何肾损伤"），然后才默认为标准成人剂量。

这确保下游 LLM 仅接收单个最相关规则，最大化精确度。

#### 2.3.4 阶段 4：基于证据的合成

在最后阶段，合成智能体接收原始处方和整理后的证据包以生成结构化审核报告。为了确保安全，智能体将不确定性处理整合到合成过程中，当证据需求超过可用患者数据时显式识别信息缺口 (I)。

当检索到的证据强加条件约束时，这至关重要。例如，如果证据指出"对于肾损伤患者必须减少剂量"，但 P 中的患者档案缺乏肾功能数据，则智能体标记这个缺口而不是幻觉结论。最终输出是一个报告，其中每个发现都明确链接到权威源文本，确保完全可追溯性。

## 3. 实验

### 3.1 HPKB 构建性能 (RQ1)

**实验设置**: 为了严格评估知识填充性能，我们从 100 份多样化药物文档构建了金标准 HPKB。注释过程由具有 10 年以上医学信息学和本体构建经验的高级临床药师进行。这位专家仔细审查源文档，并根据最终模式手动提取所有相关实体、属性值和关系。这个专家策划的数据集作为衡量不同系统提取保真度的可靠基础真相。

**基线**: 我们将分块感知多智能体框架 (PharmGraph-Auditor) 与两个强大的基线进行比较：

- **基线 1**: Zero-shot OpenIE (GraphRAG 风格)。模拟 GraphRAG 的索引阶段，在没有预定义模式约束的情况下操作。利用强大的 LLM 处理完整文档，自主识别实体，以自下而上的方式提取结构化属性元组（用于关系记录）和主 - 谓-宾三元组（用于图谱边）。

- **基线 2**: One-shot Schema-guided Agent (AutoKG 风格)。改编自 AutoKG 的信息提取模块，利用完整文档上下文结合单次演示。为了与我们的混合数据模型保持一致，我们扩展了其提示，不仅包括图谱关系的候选谓词，还包括关系表的目标字段。

**结果**: 表 3 中的定量结果表明，PharmGraph-Auditor 实现了最先进的性能，在所有指标上始终优于基线。我们的框架在召回率和精确率之间保持稳健平衡，所有测试 LLM 的 F1 分数均超过 0.83。这种平衡至关重要：高召回率 (≥0.84) 确保潜在医疗风险的全面覆盖，而高精确率 (≥0.82) 有效抑制幻觉，验证构建知识库的可信赖性。

与基线的比较：基线表现出显著的性能瓶颈。Zero-shot OpenIE（GraphRAG 风格）尽管精确率可接受，但召回率极低 (0.4860)，由于缺乏模式指导而错过了超过一半的基本事实。One-shot Schema-guided 智能体（AutoKG 风格）将召回率提高到 0.7709，但在准确性和完整性方面仍不及我们的框架。这些结果证实，单次处理复杂文档会稀释模型的注意力（"中间丢失"），而我们的分块感知多智能体方法确保细粒度和准确的提取。

### 3.2 处方审核性能 (RQ2)

**现实世界数据集**: 与合成基准不同，我们使用来自真实世界医院的 100 组真实住院患者病历和处方进行了实验。该数据集涵盖了跨科室的复杂临床场景。我们首先定义了处方风险的全面分类法，分为五个主要类型及其子类型（如图 5 所示）。因此，审核过程集中在五个类别：适应症、剂量、禁忌症、特殊人群和相互作用，总共产生 500 个不同的审核点。

**评估基线和流程**: 为了严格评估系统，我们采用了四向比较研究：

1. **经验审核**（人工基线）：由具有 10 年以上临床经验的高级药师执行，仅依赖专业记忆和专业知识。

2. **知识审核**（金标准）：同一位高级药师执行第二次审核，这次在我们的 HPKB 检索结果的辅助下进行。

3. **提议方法**（CoV）：由我们提议的 HPKB 驱动框架自动执行的审核。

4. **规则审核**（传统 CDSS）：我们将我们的方法与医院的传统临床决策支持系统进行了比较。这个前 LLM 系统维护了 20 多年，依赖于医生和药师手动编码的刚性规则，代表了劳动密集型的构建过程。

来自知识审核的特定识别问题（500 个中的 37 个）作为基础真相。这导致正确处方率为 92.6%，与现实世界场景中基线质量普遍较高的情况一致。然而，鉴于医疗环境中对错误的零容忍政策，有效的检测方法对于识别这些罕见但关键的错误仍然至关重要。

**比较性能**: 表 4 展示了我们的 AI 方法与人工基线（经验审核）和传统基于规则的 CDSS 的性能比较。结果突出了每种方法固有的不同权衡，并验证了我们提议框架的有效性。

**经验审核**: 人类药师实现了完美的精确率 (100%)，表明经验丰富的专家很少产生误报。然而，这是以安全覆盖为代价的：召回率仅为 45.9%。这个结果强调了人类记忆和注意力的关键局限性：当药师仅依赖经验时，超过一半的潜在风险被遗漏。值得注意的是，将此与金标准（同一位药师使用我们的 HPKB）进行比较，检索能力的包含将错误检测提高了约 117%。这个显著差距证实，高保真检索对于全面安全至关重要。

**基于规则的 CDSS**: 传统 CDSS 将召回率提高到 67.6%，捕获了比人工基线更广泛的错误。然而，它遭受极低的精确率 (52.1%)。规则引擎生成的警报中近一半是假阳性。在现实世界临床环境中，如此高的噪声比显著导致"警报疲劳"，可能导致药师忽略有效警告。

**提议方法**: 我们的提议方法在安全性和效率之间取得了最佳平衡。它在召回率 (70.3%) 上超越了基于规则的系统，表现出在检测风险方面卓越的敏感性。至关重要的是，它在保持高精确率 (74.3%) 的同时实现了这一点，与基于规则的基线相比显著降低了假阳性率。

总体而言，这些发现表明我们的方法作为人类药师的有效助手。我们的系统检索的知识不仅为 LLM 的推理提供基础，还为人工验证提供可解释的证据。通过 CoV 框架实现稳健的精确率和召回率，我们的方法充当可靠的过滤器，最小化遗漏风险和误报，从而显著减轻临床药师的工作量。

**按风险类型的细粒度分析**: 为了理解两个系统的不同行为，我们分析了特定错误类别的结果，如图 6 所示。

**推理与刚性**（特殊人群）：最深刻的差异出现在特殊人群类别中。基于规则的系统表现出完全失败，未能识别任何真实风险。相比之下，我们的提议方法成功识别了这些问题中的大多数。这个性能差距突出了基于规则的逻辑的根本局限性：患者约束（如肾损伤状态、老年虚弱）很少存储在结构化数据库字段中。相反，它们嵌入在非结构化临床笔记和实验室报告中。我们方法的语义推理能力使其能够从上下文中有效推断这些"软约束"。

**精确率和警报疲劳**: 与基于规则的基线相比，我们的方法在所有风险类别中实现了卓越的精确率。值得注意的是，我们在相互作用、剂量和特殊人群等类别中实现了完美或接近完美的精确率，表现出卓越的可靠性。唯一的例外是适应症类别；虽然我们的方法仍然优于基线，但两个系统相对较低的精确率分数突出了这个特定任务与其他任务相比固有的复杂性。通过通常保持如此高的精确率，我们的方法直接减轻了药师"警报疲劳"的风险——这是安全系统实际采用中的关键因素。

**"临床情境"的挑战**（适应症）：在调查适应症的较低精确率 (0.46) 后，我们发现相当一部分假阳性源于缺乏"临床情境意识"，系统严格遵守明确的药物数据，而忽视隐性临床惯例。一个典型例子是 0.9% 氯化钠（生理盐水）：在住院环境中，它常规用作溶剂或冲管，但由于这些程序性用途未在药品说明书中正式列为"治疗适应症"，LLM 错误地将它们标记为不匹配。这个发现强调了未来知识库需要用临床程序知识增强的必要性，以区分严格的医学禁忌症和公认的医院实践。

### 3.3 消融研究

为了严格验证验证链 (CoV) 框架和外部知识库的贡献，我们使用通过"红队"方法构建的高保真合成基准进行了消融研究。

**数据集构建**: 我们采用 Gemini 2.5 Pro 系统生成超过 1000 个处方测试用例。具体来说，向模型提供药品说明书，并提示合成故意违反所提供内容的错误处方。对于每个生成的案例，模型同时识别错误类型并从手册文本中引用相应的支持证据。这个生成严格按照图 5 中说明的全面风险分类法进行。为了确保数据质量，专家药师随机抽样并审查数据集，验证处方符合医学常识，错误逻辑严格遵守提示。

我们将我们的完整方法与两个变体进行了比较：(1) 无 CoV 框架，标准的全文 RAG 方法，LLM 在单次传递中阅读整个药品说明书；(2) 无 CoV 且无知识，仅依赖 LLM 内部权重的零样本设置。

如表 5 所示，移除外部知识（无 CoV 且无知识）导致 F1 分数大幅下降，证实仅内部参数知识不足以进行精确的临床审核。虽然提供完整文档（无 CoV）比零样本基线有所改善，但由于处理 lengthy 非结构化文本固有的噪声，它仍然显著低于我们提议的方法。值得注意的是，这种标准 RAG 方法也比我们提议的方法产生更高的成本，主要是由于处理完整文本的过度 token 消耗。因此，我们的完整 CoV 方法通过仅检索精确、相关的事实，实现了准确性和效率的最佳平衡。

### 3.4 案例研究：追踪验证链

为了具体说明我们系统的端到端工作流程，本节展示了基于知识库的验证链 (CoV) 框架的实际案例研究。我们追踪单个、现实的处方通过整个审核流程，从初始任务分解到最终的、基于证据的报告。这个演练（如图 7 所示）展示了 CoV 的结构化流程如何通过识别不太复杂的方法可能遗漏的关键风险来确保准确性和安全性。

**临床场景**: 我们考虑一个复杂但临床现实的场景，涉及由关键药物 - 药物相互作用引起的剂量调整。

- **患者档案**: 59 岁女性患者，诊断为 HR 阳性、HER2 阴性转移性乳腺癌和结核病。她的档案表明没有预先存在的肾或肝损伤。

- **处方订单**: 处方包括 Abemaciclib（每天两次，每次 150 mg）用于癌症治疗。至关重要的是，患者还因结核病接受利福平（每天一次，600 mg）治疗——一种强效 CYP3A4 诱导剂。

**CoV 流程**:

1. **任务分解**: 分解智能体识别需要验证的关键点：Abemaciclib 剂量、利福平相互作用、患者年龄/性别考虑。

2. **查询生成**: 
   - 对于剂量验证：生成 SQL 查询检索 Abemaciclib 剂量规则
   - 对于相互作用：生成 Cypher 查询检索 CYP3A4 代谢路径

3. **证据检索**: 
   - 从 ℛ 检索：Abemaciclib 标准剂量为 150 mg BID，但与强 CYP3A4 诱导剂合用时应增加至 200 mg BID
   - 从 𝒢 检索：利福平 → 诱导 → CYP3A4 → 代谢 → Abemaciclib

4. **证据合成**: 系统生成报告，指出当前剂量不足，建议增加至 200 mg BID，并引用具体源文本。

## 4. 相关工作

处方审核作为药物安全的关键组成部分，已从人工药师审核演变为自动化临床决策支持系统 (CDSS)。传统 CDSS 严重依赖静态、基于规则的逻辑来检测药物 - 药物相互作用 (DDI) 和剂量违规等错误。虽然在捕获显性错误方面有效，但这些系统通常因精确度差和无法处理非结构化临床叙述而遭受高警报疲劳。为了克服这些刚性问题，研究人员越来越多地将机器学习 (ML) 和深度学习技术整合到审核工作流中。

大语言模型 (LLM) 的出现为临床数据处理引入了变革性范式。在生物医学语料库上微调的基础模型，如 BioGPT、PMC-LLaMA 和 Med-PaLM 2，在从医学执照考试到复杂问答的任务中实现了专家级性能。为了增强理解，像 BALI 这样的工作提出通过将这些模型的文本表示与生物医学知识图谱对齐来增强这些模型。这些能力表明 LLM 可以作为全面的审核智能体。然而，在高风险临床决策中部署 LLM 受到幻觉的阻碍——模型生成看似合理但不正确的断言。在处方审核中，无根据的输出可能导致严重的不良药物事件。此外，LLM 推理的不透明性缺乏临床验证所需的透明度。为了减轻这些风险，检索增强生成 (RAG) 已成为将模型输出基于已验证外部知识的解决方案。

最近的研究通过超越非结构化文本检索到利用结构化知识来源推进了 RAG，产生了 GraphRAG 和医学知识图谱问答 (KGQA) 系统。像 MedGraphRAG 和 DoctorRAG 这样的框架利用知识图谱 (KG) 的拓扑结构来实现多跳推理，使系统能够追踪症状、诊断和治疗之间的关系。虽然这些以图谱为中心的方法在语义推理方面表现出色，但它们通常在处方审核固有的严格数值约束满足问题（如验证肾功能阈值或基于体重的剂量计算）方面遇到困难。这个局限性突出了语义遍历和基于集合的值过滤之间的算法差异性，表明单一数据模型不足以表示药物知识的全部范围。

这个数据建模挑战重新激发了对混合数据模型和虚拟知识图谱 (VKG) 范式的兴趣。VKG 历史上被称为基于本体的数据访问 (OBDA)，支持在异构数据源上进行统一语义查询，而无需物理迁移到图谱格式。通过将关系数据映射到概念图谱层，VKG 框架使系统能够利用 SQL 的计算效率进行数值约束，同时保留图谱查询的推理能力。信息提取 (IE) 和自动化知识库构建 (KBC) 的并行进步，如 AutoKG 和模式灵活的提取框架，使得从非结构化文本填充此类复杂架构变得可行。然而，现有的自动化 KBC 流程通常优先考虑静态模式或单模型输出，未能解决将知识分层到适合临床审核的混合存储后端的动态需求。

## 5. 结论

在本文中，我们介绍了 PharmGraph-Auditor——一个混合框架，旨在弥合 LLM 能力与临床处方审核严格安全要求之间的差距。通过通过数值约束的关系建模和语义拓扑的图谱表示形式化药物知识的不同性质，我们的系统确保了精确性和推理深度。我们引入了用于可信赖知识构建的迭代模式精炼 (ISR) 算法和用于透明推理的基于知识库的验证链 (CoV)。实验评估证实，我们的方法在 F1 分数上比传统 CDSS 高出 13.4%，有效缓解药师警报疲劳，同时在识别潜在风险方面显著超越人类专家。

未来的工作将侧重于将真实世界证据 (RWE) 整合到知识库中，以捕捉隐性临床惯例，弥合刚性药品定义与灵活医院工作流之间的差距。最终，这项工作可以为构建安全、可追溯和可解释的 AI 系统呈现新范式，用于关键临床决策支持，将 LLM 的角色从不透明生成器转变为可验证的、基于证据的推理引擎。
