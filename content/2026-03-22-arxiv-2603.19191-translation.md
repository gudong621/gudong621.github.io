## 摘要

强化学习 (RL) 有潜力提升 GUI Agent 在随机环境中的鲁棒性，然而训练过程对奖励函数的质量高度敏感。现有的奖励方法难以同时实现可扩展性和性能。

为解决这一问题，我们提出了 **OS-Themis**——一个可扩展且准确的多 Agent 评论家框架。

与单一评判者不同，OS-Themis 将轨迹分解为**可验证的里程碑**，以隔离决策所需的关键证据，并采用**审核机制**在做出最终裁决前严格审计证据链。

为促进评估，我们进一步引入了 **OmniGUIRewardBench (OGRBench)**——一个用于 GUI 结果奖励的整体跨平台基准。在该基准上，所有被评估的模型在 OS-Themis 的支持下均达到了最佳性能。

在 AndroidWorld 上的大量实验表明：
- 当用于支持**在线 RL 训练**时，OS-Themis 带来了 **10.3%** 的性能提升
- 当用于**自训练循环中的轨迹验证和过滤**时，带来了 **6.9%** 的提升

这些结果凸显了 OS-Themis 在推动 Agent 进化方面的潜力。

## 核心概念解析

### 1. GUI Agent

**定义**：能够理解和操作图形用户界面 (Graphical User Interface) 的智能 Agent。

**应用场景**：
- 手机 App 自动化操作
- 桌面软件交互
- 网页浏览任务
- 跨平台工作流自动化

**挑战**：
- 界面元素多样且动态变化
- 操作结果具有随机性（网络延迟、弹窗等）
- 需要理解视觉 + 文本 + 交互的多模态信息

### 2. 奖励函数 (Reward Function)

**定义**：在强化学习中，用于评估 Agent 行为好坏的数值信号。

**在 GUI 场景中的难点**：
- 任务完成与否往往需要多步操作后才能判断
- 中间步骤的"好坏"难以量化
- 不同任务的成功标准差异巨大

### 3. 多 Agent 评论家 (Multi-Agent Critic)

**核心思想**：用多个 specialized 的评判者替代单一的全能评判者。

**优势**：
- 每个 Agent 可以专注于特定维度（如：界面元素识别、操作序列合理性、最终结果验证）
- 降低单一模型的认知负担
- 通过投票/共识机制提高准确性

### 4. 里程碑分解 (Milestone Decomposition)

**方法**：将长轨迹拆分为多个可独立验证的子目标。

**示例**（以"在地图 App 中导航到某地"为例）：
1. ✅ 成功打开地图 App
2. ✅ 搜索框中输入了正确的目的地
3. ✅ 选择了正确的搜索结果
4. ✅ 点击了"开始导航"按钮
5. ✅ 导航界面正常显示

**好处**：
- 错误定位更精确（知道哪一步出了问题）
- 奖励信号更密集（每步都有反馈，而非只在最终）
- 便于调试和优化
