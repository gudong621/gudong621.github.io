# A Markovian Framework for Pre-Deployment Reliability and Oversight-Cost Auditing in Agentic AI

## 一句话总结

用马尔可夫过程量化 AI Agent 在企业工作流中的自主决策盲区，并提出"盲区质量"作为部署前可靠性与监管成本的统一度量。

## 核心洞察

### 问题定义
当企业流程从确定性工作流变成 Agent 的随机策略后，关键问题不再是"下一步看起来合不合理"，而是"整条轨迹是否统计上可靠、局部无歧义、经济上可控"。

### 关键概念
- **State Blind-Spot Mass** B_n(τ)：状态层面的盲区，衡量哪些工作流状态在训练数据中从未见过
- **State-Action Blind Mass** B^SA_{π,n}(τ)：更细粒度的，在特定状态下 Agent 选择某个动作的信心盲区
- **Human-in-the-loop Escalation Gate**：基于熵的自动升级门控——当 Agent 不确定时自动叫人
- **Oversight Cost Identity**：监管成本与可靠性度量的数学同一性——两者是同一枚硬币

### 实验发现
在 BPIC 2019 采购日志（251,734 案例，1,595,923 事件，42 种工作流动作）上：
- 粗粒度状态空间（42 状态）：blind mass 仅 0.0165
- 细粒度（加入案例上下文、金额、执行者类别 → 668 状态）：blind mass 飙升至 0.1253
- **核心结论：粗粒度看很安全，细粒度看暗藏风险**

### 实用价值
- m(s) = max_a π̂(a|s) 能在 3.4% 误差内预测自主步骤准确率
- 框架适用于任何有操作日志的工程流程

## 塔塔点评

这篇是我近期看到最"接地气"的 Agent 安全论文。不是空谈对齐，不是玄学评测，而是拿 25 万条真实企业数据，用量化指标告诉你：**你的 Agent 到底在哪一步可能会翻车**。

最有洞察的一点是"细粒度暴露盲区"——就像自动驾驶，在简单的驾驶场景（高速直行）里统计上很安全，但细化到雨夜+施工路段+行人横穿，风险就藏不住了。这个 analog 对 AI Agent 完全成立。

**唯一不足**：目前只验证了采购流程这一种场景，能否泛化到代码生成、数据分析等更复杂的 Agent 场景还需要验证。但框架本身是通用的，只要有日志就能用。

> 适用人群：正在部署 AI Agent 到生产环境的团队，特别是企业自动化、RPA 升级方向。
