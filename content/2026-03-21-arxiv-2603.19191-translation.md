## 摘要

强化学习 (RL) 有潜力提升 GUI Agent 在随机环境中的鲁棒性，然而训练过程对奖励函数的质量高度敏感。现有的奖励方法难以同时实现可扩展性和性能。

为此，我们提出了 **OS-Themis**——一个可扩展且准确的多智能体评论框架。与单一评判者不同，OS-Themis 将轨迹分解为可验证的里程碑，以隔离决策的关键证据，并采用审查机制在做出最终裁决前严格审核证据链。

为了促进评估，我们进一步引入了 **OmniGUIRewardBench (OGRBench)**——一个用于 GUI 结果奖励的整体跨平台基准。在该基准上，所有被评估的模型在 OS-Themis 的支持下都达到了最佳性能。

在 AndroidWorld 上的大量实验表明：
- 当 OS-Themis 用于支持**在线 RL 训练**时，产生了 **10.3%** 的性能提升
- 当用于**自训练循环中的轨迹验证和过滤**时，产生了 **6.9%** 的提升

这些结果突显了 OS-Themis 在驱动 Agent 进化方面的潜力。

## 核心贡献

### 1. 问题背景

GUI Agent 在现实世界应用中面临诸多挑战：
- 环境具有随机性（网络延迟、UI 渲染变化、用户输入不确定性等）
- 强化学习是提升鲁棒性的有效途径
- 但 RL 训练极度依赖奖励函数的设计质量

现有奖励方法的困境：
- **可扩展性不足**：细粒度奖励需要大量人工标注
- **性能受限**：粗粒度奖励无法提供足够的学习信号
- **单点偏差**：单一评判者容易产生系统性错误

### 2. OS-Themis 框架设计

#### 2.1 轨迹分解 (Trajectory Decomposition)

OS-Themis 的核心思想是将完整的 GUI 操作轨迹分解为多个**可验证的里程碑**：

```
完整轨迹：打开应用 → 搜索内容 → 筛选结果 → 点击详情 → 保存信息
                ↓           ↓           ↓           ↓
里程碑 1       里程碑 2     里程碑 3     里程碑 4     里程碑 5
```

每个里程碑的特点：
- **独立性**：可单独验证成功/失败
- **可观测性**：有明确的界面状态作为证据
- **可组合性**：多个里程碑组合形成完整任务的成功标准

#### 2.2 多智能体评论架构

OS-Themis 采用多智能体协作的评论机制：

1. **证据收集 Agent**：负责从每个里程碑提取关键证据
2. **验证 Agent**：独立验证每个证据的有效性
3. **审查 Agent**：审核证据链的完整性和一致性
4. **裁决 Agent**：基于审核结果做出最终奖励判断

这种设计的优势：
- **减少偏差**：多个独立视角相互验证
- **错误隔离**：单个 Agent 的错误不会污染整个评判
- **可解释性**：每个决策都有明确的证据链支持

#### 2.3 证据链审核机制

在做出最终裁决前，OS-Themis 执行严格的证据链审核：

```
证据收集 → 交叉验证 → 一致性检查 → 完整性评估 → 最终裁决
```

审核标准：
- **相关性**：证据是否与当前里程碑直接相关
- **充分性**：证据是否足以支持成功/失败的判断
- **一致性**：不同证据之间是否存在矛盾
- **完整性**：是否覆盖了所有关键决策点

### 3. OmniGUIRewardBench (OGRBench)

为了系统评估 GUI 奖励方法，作者提出了 OGRBench 基准：

**特点**：
- **跨平台**：覆盖 Android、iOS、Web、桌面等多个平台
- **整体性**：包含多样化的任务类型和复杂度
- **标准化**：统一的评估协议和指标

**评估结果**：
- 所有被评估的模型在 OS-Themis 支持下都达到了最佳性能
- 证明了 OS-Themis 的通用性和有效性

### 4. 实验结果

#### 4.1 实验设置

- **主要基准**: AndroidWorld
- **对比方法**: 现有主流 GUI 奖励方法
- **评估指标**: 任务成功率、训练效率、泛化能力

#### 4.2 主要结果

| 应用场景 | 性能提升 | 说明 |
|---------|---------|------|
| 在线 RL 训练 | +10.3% | 直接用于训练过程中的奖励信号 |
| 轨迹验证过滤 | +6.9% | 用于自训练循环中的数据筛选 |

#### 4.3 关键发现

1. **奖励质量直接影响训练效率**：高质量的奖励信号可以显著减少训练所需的样本数
2. **里程碑分解提升可解释性**：可以精确定位 Agent 在哪个步骤失败
3. **多智能体互审减少错误传播**：避免了错误奖励导致的错误学习

## 技术启示

### 对 GUI Agent 开发的启示

1. **不要依赖单一奖励信号**：复杂的 GUI 任务需要多层次、多角度的评估
2. **分解是王道**：将长序列任务分解为可验证的子任务是提升性能的关键
3. **证据链思维**：每个判断都应该有可追溯的证据支持

### 对强化学习应用的启示

1. **奖励工程值得投入**：好的奖励设计可以带来 10%+ 的性能提升
2. **可解释性很重要**：能够解释"为什么成功/失败"比单纯的成败判断更有价值
3. **自训练循环需要质量控制**：用高质量评论器过滤训练数据可以提升自训练效果

---

## 总结

OS-Themis 通过创新的**多智能体评论框架**和**轨迹分解方法**，为 GUI Agent 的强化学习训练提供了高质量的奖励信号。实验证明该方法在多个应用场景下都能带来显著的性能提升，是 GUI Agent 奖励设计领域的重要进展。
